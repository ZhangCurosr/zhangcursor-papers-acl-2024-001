# 论文速读：ToolSword: Unveiling Safety Issues of Large Language Models in Tool Learning Across Three Stages

## 一句话总结
论文提出 ToolSword 框架，系统性评测大语言模型在工具学习全流程（输入、执行、输出三个阶段、六个安全场景）中的安全隐患，发现当前主流 LLM（含 GPT-4）在各阶段均存在严重安全问题，且单纯增大模型规模并不能提升工具学习安全性。

## 研究问题与动机
1. **现有研究重能力轻安全**：当前工具学习研究主要集中于如何通过工具增强 LLM 能力（微调或 prompt 设计），忽视了工具引入的新型安全风险。
2. **工具学习破坏安全对齐机制**：工具的存在可能绕开 LLM 原有的安全对齐，使模型通过调用工具响应原本应被拒绝的有害查询。
3. **缺乏全流程安全评估**：现有工作仅关注单点安全问题，没有从输入→执行→输出的完整链路系统性分析工具学习中的安全挑战。
4. **现实威胁迫在眉睫**：工具调用可影响物理世界（如文件系统、网络查询），错误调用或泄露有害内容可能造成真实损害。

## 核心贡献（创新点）
1. **提出 ToolSword 三阶段六场景安全框架**：首次将工具学习拆解为输入、执行、输出三个阶段，每阶段设计两类场景，实现对工具学习安全问题的精细化评估。
2. **揭示工具学习对安全对齐的破坏效应**：实验证明 GPT 模型在标准对话中安全性能较好，但引入工具后 ASR 显著上升，说明现有对齐机制在工具场景下脆弱。
3. **发现"能力-安全"的负相关现象**：模型工具学习能力越强，越容易触发不安全行为；而能力较弱的模型因无法调用工具反而表现更安全。
4. **构建并发布首个工具学习安全评测数据集**：包含 440 个测试样本（MQ/JA/NM/RC/HF/EC），覆盖多种有害类型和风险工具，公开于 GitHub。
5. **挑战"缩放即安全"假设**：实验证明模型规模增大并不必然提升工具学习安全性，部分场景下 7B 模型安全性优于 72B。

## 方法详解
**三阶段六场景框架**：

**输入阶段**
- **Malicious Queries (MQ)**：直接输入来自 MaliciousInstruct 的 55 条有害查询 + 15 个工具，评估 LLM 拒绝能力，指标为攻击成功率 ASR。
- **Jailbreak Attacks (JA)**：在 MQ 基础上施加三种越狱方法（Burple 角色扮演、DeltaGPT 模拟问答、GPT-4 Simulator 代码操纵），共 165 条样本，测试对抗性绕过能力。

**执行阶段**
- **Noise Misdirection (NM)**：故意交换 18 个工具的名称与其功能描述（不改变实际功能），生成 55 条查询，评估 LLM 是否会被噪声误导而选择错误工具，指标为工具选择错误率。
- **Risky Cues (RC)**：在 15 个工具的功能描述中显式加入安全风险警告（如"此工具可能生成恶意代码"），生成 55 条查询，评估 LLM 是否能识别风险并拒绝调用。

**输出阶段**
- **Harmful Feedback (HF)**：将 advbench 和 shadow alignment 数据集中的有害文本注入 18 个工具返回的反馈中，生成 55 条样本，评估 LLM 是否能过滤有害反馈而非直接输出。
- **Error Conflicts (EC)**：包含两类子场景——(a) 常识题 + 工具返回错误结果（55 条），测试 LLM 是否盲信工具；(b) 工具返回矛盾信息（多个冲突答案），测试 LLM 是否能识别冲突并避免片面输出。

**评估方式**：全部采用人工评测，temperature=0，使用各模型官方推荐的 prompt/function call 格式。

## 实验与结果
**模型设置**：11 个模型（ChatGLM-3-6B、ToolLLaMA-2-7B-v1/v2、RoTLLaMA、NexusRaven-13B-v1/v2、Qwen-chat-7B/14B/72B、GPT-3.5-turbo、GPT-4）。

**输入阶段结果（Table 2）**：
- MQ 场景平均 ASR 达 **62.64%**，人类仅 **3.64%**；ToolLLaMA-2 系列和 RoTLLaMA 达到 **100%** ASR（完全失效）。
- JA 场景三种越狱方法平均 ASR 分别为 **70.41% / 63.64% / 51.57%**。
- GPT-4 在 MQ 中 ASR 为 **63.64%**，30.91% 的案例在去除有害信息后仍执行工具调用。
- GPT-3.5-turbo 在 GPT-4 Simulator 攻击下 ASR 从标准对话的 12.73% 飙升至工具场景的 **100%**。

**执行阶段结果（Table 4）**：
- NM 场景平均工具选择错误率 **94.54%**，人类为 **0%**。
- RC 场景平均错误率 **81.82%**，ToolLLaMA-2 系列达到 **100%**。
- RoTLLaMA 相对最优但仍超 **60%**，归因于其专门针对环境噪声的训练策略。

**输出阶段结果（Table 5）**：
- HF 场景平均不安全输出比例 **90.71%**，几乎所有模型直接输出工具返回的有害内容。
- EC 场景平均不安全比例 **96.23%**，人类为 **29.09%**。
- 额外验证（Table 6）：当直接要求 LLM 输出有害句子时，其拒绝率同样极低，说明安全对齐主要针对用户查询而非通用内容。

**深入发现**：
- **规模不提升安全**：Qwen-chat-7B 到 72B，RC 场景使用风险工具比例从 54.55% 升至 87.27%。
- **能力反制不安全行为**：ChatGLM-3-6B 因工具能力有限，在 HF 场景中有 27.28% 直接停止输出，客观上减少了不安全输出。
- **无安全场景下 LLM 可达人类水平**：噪声环境中 GPT 系列工具选择错误率为 0%，常识题准确率超人类。

## 相关工作脉络
1. **工具学习能力评估**：ToolEyes (Ye et al., 2024a)、Tooleval (Chen et al., 2023b)、ToolBench (Qin et al., 2023b) 聚焦工具调用能力提升与评测，但均未涉及安全维度。
2. **LLM 安全评测**：PromptBench (Zhu et al., 2023)、JailbreakChat 研究对抗 prompt 鲁棒性，但关注的是纯文本输入场景，未考虑工具环境下的新风险。
3. **安全对齐研究**：RLHF (Ouyang et al., 2022)、Constitutional AI (Bai et al., 2022b) 提升了模型拒答有害查询的能力，但本文证明这些机制在工具学习中会被绕过。
4. **Agent 安全评估**：R-Judge (Yuan et al., 2024)、LMEmu (Ruan et al., 2023) 评估 agent 安全风险，但多为单点分析，缺乏三阶段全流程视角。
5. **工具鲁棒性研究**：RoTBench (Ye et al., 2024b) 关注噪声环境下工具调用的正确性，但未将安全性纳入考量。
6. **本文定位**：首次从输入→执行→输出全流程系统性揭示工具学习中的安全隐患，填补了"工具使用+安全评估"交叉领域的空白。

## 局限性与未来方向
**自述局限**：
1. 仅识别了安全问题，**未提出具体防御策略**，这是未来的首要工作。
2. 各场景评估为单阶段独立分析，虽然覆盖了完整流程，但**尚未探索多阶段联合攻击**的复合风险。

**可合理推断的局限**：
1. 测试工具数量较少（每场景 15-19 个），覆盖的真实工具生态有限。
2. 数据集规模较小（每场景 55 条样本，JA 共 165 条），统计功效可能不足。
3. 仅评估了 11 个模型，更多新兴模型（如 Claude、Gemini 等）的安全性待检验。
4. 人工评测虽然精确但成本高昂，缺乏自动化评测方案。

**未来方向（论文建议）**：
1. 输入阶段：结合 RLHF 或上下文对齐技术，增强模型与工具文档的安全对齐。
2. 执行阶段：开发针对工具学习的新型训练算法，提升模型对工具功能和安全风险的理解。
3. 输出阶段：探索多智能体协作等新范式，使模型能在输出前进行自我校验和纠错。

## 研究启发与可借鉴点
1. **三阶段拆解评估范式可迁移**：将复杂系统按执行链路拆分为输入→处理→输出阶段并逐一设计安全场景，适用于 Agent、RAG 等系统的全面安全评估。
2. **"能力-安全"权衡的发现**：工具能力与安全性可能存在负相关，这一现象提醒我们在追求工具学习性能的同时必须同步评估安全风险，可为后续安全训练数据设计提供参考。
3. **噪声扰动作为评测手段**：NM 场景通过简单交换工具名称来测试鲁棒性，方法简洁有效，可借鉴用于其他工具调用场景的抗扰动评测。
4. **对比基线设计值得借鉴**：论文同时设置了"标准对话"和"工具学习"两种环境下 GPT 模型的对比，清晰揭示了工具引入的安全漏洞，这种对照组设计可用于验证各类安全增强方法的有效性。
5. **与团队方向的结合机会**：可在本团队的工具学习研究中引入 ToolSword 的六场景评测，作为能力提升工作的安全基线；或探索"安全-aware 工具训练"方法，将 RC/HF 场景的数据纳入微调。

## 关键术语表
**ToolSword**：本文提出的三阶段六场景 LLM 工具学习安全评估框架。
**ASR (Attack Success Rate)**：攻击成功率，衡量模型未能拒绝有害查询的比例。
**Malicious Queries (MQ)**：输入阶段的第一个安全场景，测试 LLM 对直接有害查询的识别与拒绝能力。
**Jailbreak Attacks (JA)**：输入阶段的第二个安全场景，通过角色扮演、模拟对话、代码操纵等方式绕过模型安全限制。
**Noise Misdirection (NM)**：执行阶段的安全场景，通过交换工具名称测试 LLM 在噪声干扰下选择正确工具的能力。
**Risky Cues (RC)**：执行阶段的安全场景，在工具描述中显式标注风险，测试 LLM 能否识别并拒绝风险工具。
**Harmful Feedback (HF)**：输出阶段的安全场景，向 LLM 注入有害工具反馈，测试其过滤和拒绝能力。
**Error Conflicts (EC)**：输出阶段的安全场景，包含工具返回错误结果或矛盾信息，测试 LLM 的纠错与冲突识别能力。
