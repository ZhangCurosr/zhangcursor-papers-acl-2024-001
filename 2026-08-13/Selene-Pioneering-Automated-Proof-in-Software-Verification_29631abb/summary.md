# 论文速读：Selene: Pioneering Automated Proof in Software Verification

## 一句话总结
本文提出了首个基于真实工业级操作系统微内核 seL4 的项目级自动化证明基准 Selene，并通过引理隔离技术构建了轻量级验证环境；实验表明 GPT-4 等 LLM 具备在软件验证领域进行自动化证明生成的潜力，且三种增强策略（相似引理、依赖、错误修复）能有效缓解挑战。

## 研究问题与动机
1.  **核心问题**：软件形式化验证中的证明生成阶段极其耗时耗力（如 seL4 需 11 人年），亟需自动化。
2.  **现有方法不足**：现有基于 LLM 的研究多集中于数学定理证明或函数级代码验证，缺乏针对包含复杂依赖关系的真实工业级项目（如整个 OS 微内核）的自动化证明基准与框架。

## 核心贡献（创新点）
1.  **提出 Selene 基准**：首个基于真实工业项目 seL4 构建的项目级自动化证明基准，覆盖 360 个引理，填补了该领域空白。
2.  **引理隔离技术**：创新性地将目标引理从其复杂依赖图中隔离出来，构建独立的轻量级验证会话，将验证时间从数十分钟降至数秒，解决了大型项目评估开销过大的瓶颈。
3.  **验证 LLM 能力与探索增强**：证明了 GPT-4 在简单证明（P1）上能达到 51.8% (ACC#5) 的准确率，并系统性地提出了相似引理、依赖信息和错误消息三种增强策略，显著提升了模型性能。

## 方法详解
1.  **基准构建**：从 seL4 的 Isabelle 验证代码中解析引理，按证明长度将程序化风格（procedural）引理分为 P1（1行）、P2（2-6行）、P3（7-20行）三个难度等级，并纳入全部 45 个声明式风格（declarative）引理，最终抽样 360 个构成基准。
2.  **引理隔离 (Lemma Isolation)**：将原始 seL4 会话拆分为目标会话（仅含目标引理及其直接前置内容）和依赖会话（包含所有上游依赖）。依赖会话验证结果持久化，目标会话只需验证自身引理，从而避免了重复构建庞大依赖图的开销。
3.  **评估流程**：将引理规范（Specification）作为输入提示给 LLM，生成 Isabelle 证明代码，随后在隔离的轻量环境中用 Isabelle 定理证明器检查其正确性。以 ACC#k（k 次尝试中至少一次成功的比例）为指标。
4.  **增强策略**：
    *   **相似引理增强**：使用 BM25 从 seL4 知识库中检索与目标规范最相似的文本块（前10行）作为上下文辅助生成。
    *   **依赖增强**：从真实证明中抽取已应用的定理/定义，定位其在 seL4 源码中的出处（前5行）提供给 LLM，以减少“未定义事实”错误。
    *   **错误修复增强**：采用两轮对话机制，若第一轮证明失败，将 Isabelle 生成的错误信息反馈给 LLM 进行修正。

## 实验与结果
*   **数据集**：Selene 基准，共 360 个引理（P1: 139, P2: 104, P3: 59, D: 38）。
*   **评估基线**：GPT-3.5-turbo, GPT-4。
*   **主要结果**：
    *   基础设置下，GPT-4 在 P1 类别达到最高准确率 **51.8% (ACC#5)**，GPT-3.5-turbo 为 35.3%。难度越高，性能下降越显著（P3 类别 GPT-4 仅 1.7%）。
    *   声明式证明（D）的表现优于复杂程序化证明（P3）。
    *   **增强效果**：GPT-4 + 依赖增强在 P1 上提升至 **52.5%**；GPT-4 + 相似增强 + 修复增强在 P1 上达到 **61.9%**，在 P2 上达到 **20.2%**。错误分析显示，依赖增强有效减少了“未定义错误”，修复增强减少了“逻辑错误”。
*   **最强结果**：GPT-4 + 相似增强 + 修复增强组合，在 P1 引理上实现 **61.9%** 的 ACC#1 准确率。

## 相关工作脉络
1.  **自动化定理证明 (LLM)**：如 Thor (集成LLM与hammer)、DSP (生成形式化草稿)、Baldur/Lyra (利用错误信息修复证明)。本文与之区别在于任务领域是**工业软件验证**而非数学定理，且关注**项目级复杂依赖**。
2.  **形式化证明基准**：如 MiniF2F (数学奥赛题)、PISA (Isabelle归档)、LeanDojo (Lean语言大规模基准)。本文的 Selene 是首个基于**真实工业操作系统**的自动化证明基准。
3.  **自动化软件验证**：传统技术包括静态分析、模型检查等。本文聚焦于**交互式定理证明器辅助的自动证明生成**这一较新方向。
4.  **LLM辅助代码验证**：如 Clover (基于 Dafny 的语言规范一致性检查)、Yao et al. (基于 Rust 的函数级不变式生成)。本文突破点在于处理**完整的、具有深厚领域知识的大型项目**（seL4），而非独立函数。
5.  **检索增强生成 (RAG)**：Similar lemma 增强借鉴了 RAG (Lewis et al., 2020) 的思想，将其应用于形式化证明生成领域。
6.  **交互式证明状态**：文中提及 PISA (Jiang et al., 2021) 的 Scala-Isabelle 框架可用于获取证明状态，实现交互式证明，这与本工作的孤立会话设计正交，是未来结合的方向。

## 局限性与未来方向
1.  **依赖提取不准确**：目前依赖增强依赖人工从真实证明中提取事实，未来计划结合更先进的 RAG 技术自动从代码库中提取候选事实。
2.  **仅关注证明阶段**：未涉及规格说明（Specification）生成阶段的自动化，该阶段同样需要大量人力。
3.  **端到端生成局限**：当前框架仅支持一次性生成完整证明，对于复杂证明（如 P3），人类专家也是逐步构造的。未来计划引入交互式证明状态（如结合 PISA），模拟人类逐步构造证明的过程。

## 研究启发与可借鉴点
1.  **大型项目评估的工程化设计**：“引理隔离”思想极具价值，为解决大型形式化系统或复杂代码库的评估开销问题提供了通用思路：通过剥离和隔离依赖来创建轻量级、可快速迭代的测试/评估环境。
2.  **多维度增强策略的组合**：提出的三种增强策略分别针对 LLM 在形式化验证中遇到的不同痛点（知识缺乏、上下文不足、纠错能力），其组合使用的实验设计对后续研究有直接参考价值。
3.  **错误类型学分析**：对 LLM 生成证明的错误进行了细致分类（未定义错误、逻辑错误、其他错误），并分析了增强策略对各类错误的改善效果，这种分析框架有助于定位模型瓶颈和指导改进方向。
4.  **程序化 vs 声明式证明风格对比**：实验中发现 LLM 在更易读的声明式证明上表现更好，这为如何更好地将工业代码的验证证明转化为适合 LLM 处理的格式提供了启发。
5.  **未来工作方向明确**：将 RAG 引入自动依赖提取、结合交互式证明状态，是两个非常清晰且具有可行性的后续研究路径，可直接作为本团队或他人的研究切入点。

## 关键术语表
**seL4**：一个经过全面形式化验证的、高度可信的操作系统微内核项目，本文的实验基础。
**Isabelle**：一种交互式定理证明器，selene 中的规范和证明均使用其形式化语言书写。
**引理隔离 (Lemma Isolation)**：Selene 的核心技术，将待验证的引理及其必要依赖分离到独立的会话中，以实现快速评估。
**程序化证明 (Procedural Proof)**：seL4 中主要的证明风格，指出一系列要应用的证明策略（tactics）序列，而不显式展示中间目标。
**声明式证明 (Declarative Proof)**：证明中明确写出中间目标和操作，可读性更强，在 seL4 中较少见。
**ACC#k**：评估指标，指在 k 次独立生成尝试中，至少有一次证明能通过 Isabelle 验证的比例。
**BM25**：一种用于文本检索的经典算法，本文用于检索与目标规范相似的引理片段。
